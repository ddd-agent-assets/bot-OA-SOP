# 01 机器人能做什么：读要授权，写只能写自己建的表

**给所有部门的一句话**：企微最新版本（已全面开放、不限企业规模）允许智能机器人直接操作企微里的办公数据——消息、邮件、文档、表格、日程、会议、网盘都能接入；但文档是"有限"访问：**读要本人授权，写只能写自己新建的**。

## 一、这些能力现在就能用

**所有人日常用得上：**

| 能力 | 能做什么 |
| :--- | :--- |
| 消息 | 向群推送通知（异常告警、日报）——仅限与机器人有过对话的群 |
| 通讯录 | 按姓名/拼音搜同事、查成员信息 |
| 待办 | 创建/分派/完成待办，可做任务提醒 |
| 邮件 | 发送/回复/转发/检索、读正文（如自动汇总客户来信） |

**行政与管理层的得力帮手：**

| 能力 | 能做什么 |
| :--- | :--- |
| 日程 | 创建/修改日程、查参会人闲忙、预订会议室 |
| 会议 | 预约/取消会议，**自动获取会议纪要与转写原文**（开会不必专人记录） |

**业务/客服用得最多（文档表格类）：**

| 能力 | 能做什么 |
| :--- | :--- |
| 文档 | 新建/导入、读取内容、追加内容、整体覆盖写 |
| 文档管理 | 搜索各类文档；文档/表格的重命名、成员权限与加入规则管理 |
| 在线表格 | 导入 Excel/CSV、读取修改、追加行 |
| 智能表格 | 管理子表/字段/记录/视图/图表（数据库型表格，适合做台账） |
| 智能文档 | 创建、读取、编辑及其内置数据表 |
| 微盘 | 搜索、上传、下载企业网盘文件 |

> 给 IT 的一句话：接入走官方工具（`@wecom/cli`）或 MCP 通道（长连接），**不需要公网服务器**，内网也能部署。

## 二、但有三条边界：写限自己建的表、读要授权、不冒充员工

### 边界一：机器人只能写"自己建的"

- 员工创建的表，机器人**永远改不了**；机器人自己新建的表随便写
- 这不是权限没配好，是企微的硬性设计，**找谁审批都没用**
- "把表共享给机器人、给它编辑权限"这条路实测同样走不通，不用再试
- 解法：新增数据让机器人建新表来记，旧表保留历史、挂索引指向新表（为什么必须这样见 [[02-提审/04-必须走的流程-企微强制没有商量|提审篇：必须走的流程]]）；建表时可打开"企业内成员自助加入"，同事打开这张表就自动获得编辑权，不用逐个加人

### 边界二：读要本人授权，且只读不写

- 员工用企微**扫码**授权后，机器人才能读这个员工可见的文档；大企业通常还需把**文档链接发给机器人一次**
- 授权永远只给"读"，不存在"授权后机器人能改我表格"的选项

### 边界三：机器人就是机器人，不能冒充员工

- 不能以某位员工的名义发消息
- 授权了工具的机器人，**只有创建者本人能跟它对话**（防止权限外借）

## 三、Workbuddy 能直接接入，但同样受这三条边界约束

1. **官方点名的适配工具之一**（同批还有 Codex、Kimi Work 等）。它的"企微连接器"是官方能力的一键安装包装，**不是独占通道**——企业也可以不经 Workbuddy、直接用官方工具接入
2. **搭好的机器人能内嵌企微**：群里 @机器人 即可调用。真实案例：DDD 客服自建的"补料机器人"——原来要求手机电脑同时在线，周末不在办公室就断联；改为群内 @机器人 后，随时响应
3. **Workbuddy 同样受三条边界约束**——"读要授权、写只写自建、不冒充员工"是企微统一规则，选型时别指望任何工具绕开

## 四、各部门速查

| 部门 | 现在就能受益的事 | 要注意的事 |
| :--- | :--- | :--- |
| 客服 | 群内问答机器人、异常信息整理与通知、知识库自动回复 | 现有登记表机器人写不进，新增数据走机器人新表 |
| 业务/销售 | 询盘自动登记、船期/订单信息定时汇总、客户邮件自动整理 | 读业务表需数据负责人扫码授权并发送文档链接 |
| 行政 | 通知/加班餐信息定时搬运、会议纪要自动生成、会议室预订 | — |
| IT/管理员 | 机器人统一创建与配置可用范围；无公网服务器要求 | 机器人默认权限最小化，需管理员逐项开启 |

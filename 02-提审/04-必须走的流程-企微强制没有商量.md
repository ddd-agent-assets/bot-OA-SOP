# 04 必须走的流程：企微强制，没有商量

**结论**：这一篇写的不是我们设计的制度，是企微平台**强制**的必要流程——要么是企微自带的必须步骤（建机器人、发布审批、授权、发链接），要么是从刚性约束**引申**出的必然做法（旧表写不进就必须新表承接）。不走完，机器人就用不了；少走一步，就会出现"批了权限还是用不了"。

## 一、企微自带的必须步骤（四步）

| 必须步骤 | 为什么是必须的 |
| :--- | :--- |
| **机器人必须由管理员创建** | 业务同事自己建不了企微机器人，必须 DIC IT（超级管理员）创建并开权限——没有第二条路 |
| **发布必须过两轮审批** | 机器人建好后要发布才能用，发布自带**上级审批 + 企微管理员审批**两轮；上级审批人是提交者自己选的，系统不会自动带直属上级，要自觉选对人 |
| **授权必须搭建者本人扫码** | 机器人要读谁的文档，谁本人扫码授权（通常就是搭建者 builder，不是管理员）——**不能代办、不能批量** |
| **大企业必须发文档链接** | 每个要读的文档，链接必须发给机器人一次，否则就是"无权限" |

操作细节（谁做、在哪点、多久一次）见 [[01-创建/02-创建机器人-管理员建号开权限|创建篇]]、[[02-提审/01-发布先过两轮审批-上级加管理员|发布审批]]、[[02-提审/02-授权三步-建号扫码发链接|授权三步]]。

## 二、刚性约束引申的必然做法

平台红线（[[01-创建/01-机器人能做什么-读要授权写只能写自己建的表|创建篇01]]的三条边界）逼出来的流程，同样没有商量余地：

| 平台红线 | 引申出的必然做法 |
| :--- | :--- |
| 机器人写不了员工建的旧表 | **新增数据必须进机器人自建的新表**——"授权后机器人往旧表里写"这条路不存在 |
| 新旧表并存会出"两个真相" | **旧表必须挂索引指向新表**，并白纸黑字定下"哪个表算数、什么时候切换" |
| 机器人只有创建者本人能用 | **谁用谁建、一人一个机器人**——团队共用一个机器人行不通，每人各自申请 |
| 权限不跟人走 | **换负责人必须重新扫码授权+重发文档链接**——调岗交接时权限要重走一遍，不会自动转移 |
| "下载-上传"改表会覆盖别人的修改 | **多人共用的表必须禁用"下载-上传"方式**；机器人改动过的格子加底色标记 |
| 机器人自建的表，管理员就是机器人+搭建者，且没有"设管理者"入口 | **不要再把文档管理员授权给其他人**——机器人自建的文档，机器人和搭建者（builder）默认就是管理员，这就够了；同事要**编辑权**→建表时开"企业内自助加入"（打开表即得）；要**管理权**→界面上没有入口，兜底找企微超级管理员（目前是 AIC 的 Rosetta），别当配置问题排查（需要核对同事账号时，让对方在企微"个人信息"页自查后报给管理员） |

## 三、一句话记住

> 四个必须步骤（第一节）+ 六个必然做法（第二节）是**地板**，不是天花板——地板之上的管理设计（数据分级、审批限时、业务侧bot管理员等）是我们自己的提议，见 [[01-提议-组织SOP|组织SOP提议]]。
